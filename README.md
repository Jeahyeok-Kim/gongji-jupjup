# 공지 줍줍

건국대학교 GLOCAL캠퍼스 게시판에 흩어진 공지를 한곳에 모아, 내 시간표와 남는 시간에 맞는 것만 골라 주고 유학생에게는 영어·중국어·일본어로 보여 주는 웹 서비스입니다. (컴퓨터공학개론 기말 프로젝트, 김재혁)

```
크롬 확장 v1 (collector)        →   내 컴퓨터 (메인 서버 역할)                       →   웹 앱 (index.html)
6시간마다 백그라운드 탭으로          수신 서버 receiver.py (127.0.0.1:8765)                PC·휴대폰에서 보기
학교 게시판 새 글만 수집              → 1분 뒤 파이프라인: 로컬 AI(Ollama·Qwen) 해독·번역      (AI 키 필요 없음)
→ 수신 서버로 바로 전달               + 근거 문장 확인 → data/notices.js
(서버가 꺼져 있으면 다운로드 폴더)     AI가 꺼져 있으면: 저장된 AI 답 → 직전 결과 → 규칙 1차 정리
                                    → 백업(zip) → 게시(data/*.json + version.json)
                                                            ↓ 웹 앱이 version.json을 보고 새 데이터만 자동으로 받음
```

> `data/notices.js`에 처음 들어 있는 공지 13건은 화면 개발용 **샘플**입니다. 실제 학교 공지가 아닙니다. 파이프라인을 한 번 돌리면 실제 공지로 바뀌고, 샘플은 `data/notices.sample.js`로 백업됩니다.

## 1. 웹 앱 보기

- `index.html`을 더블클릭하면 브라우저에서 바로 열립니다. 설치할 것도, 서버도 필요 없습니다. (파일로 열면 서비스 워커·자동 갱신·구독 주소는 꺼지고, 웹 주소로 열면 모두 켜집니다.)
- PC는 왼쪽 내비게이션, 휴대폰(또는 좁은 창)은 아래 탭으로 같은 다섯 화면(오늘 · 공지 · 시간표 · 추천 · 설정)을 오갑니다. 주소 끝에 `#/home`, `#/notices`, `#/timetable`, `#/budget`, `#/settings`를 붙이면 그 탭이 바로 열리고, 뒤로 가기 버튼으로 이전 탭으로 돌아갑니다.
- 시연할 때 기준 날짜를 바꾸려면 주소 끝에 `?today=2026-11-16`을 붙입니다.

**화면과 사용 편의**
- **다크·라이트 모드**: 위쪽의 달/해 아이콘으로 바꿉니다. 처음엔 기기 설정을 따르고(자동), 설정 탭에서 자동·라이트·다크를 고를 수 있습니다. 고른 값은 브라우저에 저장되고, 화면이 깜빡이지 않도록 `index.html` 맨 위의 짧은 스크립트가 먼저 적용합니다. 글자 크기(작게·보통·크게)도 설정 탭에 있습니다.
- **모두 같은 모양의 요약**: 모든 카드에 `대상 / 마감 / 혜택 / 일정` 핵심 정보 칸이 똑같은 순서로 나오고, 그 위에 AI가 쓴 한두 문장 요약이 붙습니다. 요약이 비었거나 너무 짧거나 제목을 베꼈거나 번역에서 날짜·금액이 빠졌으면 화면이 그 요약을 숨기고 핵심 정보 칸만 보여 줍니다(`js/summary.js`).
- **읽음 · 저장(★) · 지원 완료**: 연 공지는 읽음으로 표시되고(안 읽은 공지만 모아 볼 수 있음), ★로 저장한 공지는 마감이 가까워지면 알림에 올라옵니다. "지원 완료"로 표시한 공지는 알림과 추천에서 빠지고, 방금 한 동작은 "되돌리기" 토스트로 취소할 수 있습니다.
- **관심 분야·키워드와 알림 센터**: 설정 탭 "나에게 맞게"에서 관심 분야와 키워드(예: 장학, 해외, 인턴, 10개까지)를 정해 두면 오늘 탭에 "내 관심 새 공지"가 모이고, 종 아이콘의 알림 센터에 저장한 공지의 마감과 내 키워드·관심 분야에 맞는 새 공지가 모입니다. 브라우저 알림을 켜면 **앱을 열어 둔 동안** 저장한 공지의 마감이 가까울 때 알려 줍니다. **앱이 닫혀 있을 때의 서버 푸시 알림은 아직 없습니다.**
- **검색 편의**: 띄어 쓴 낱말은 모두 들어간 공지를 찾고(예: `장학 신청`), 대상·혜택·행사까지 찾습니다. 초성 검색(`ㅈㅎㄱ` → 장학금, 제목에서만), 낱말마다 강조, 제목에 검색어가 다 들어간 공지를 먼저 보여 줍니다. 결과가 없으면 검색 도움말과 "마감 지난 공지까지 찾기" 버튼이 나옵니다. 최근 검색어, 목록 끝에 닿으면 다음 30건을 저절로 불러옵니다. PC에서는 `/` 키로 검색 칸에 바로 갑니다.
- **상세 창 넘겨 보기**: 공지를 열면 위에 "3 / 107"과 ‹ › 버튼이 생깁니다. PC는 ← → 키(S 키로 저장, Esc로 닫기), 휴대폰은 옆으로 밀어서 이전·다음 공지로 갑니다. 목록에서 열면 목록 순서, 오늘 화면·추천에서 열면 그 칸의 순서를 따릅니다. 상세 맨 아래에는 같은 혜택 종류의 **비슷한 공지** 3개가 나오고, 지원 완료·캘린더·공유 버튼은 핵심 정보 바로 아래에 있습니다. 휴대폰에서는 시트 손잡이를 끌어 내려 닫습니다.
- **마감 확인 표시**: 파이프라인이 AI가 읽은 마감과 규칙으로 읽은 마감이 다르다고 표시한 공지는 카드에 "마감 확인 필요", 상세에 다른 날짜가 적힌 원문 줄이 나옵니다. (아래 3번 "교차 확인")
- **보던 곳 기억**: 공지 목록을 내려 보다 다른 화면에 갔다 와도 보던 위치로 돌아옵니다. 시간표는 오늘 요일 칸과 지금 시각(빨간 줄)을 보여 줍니다. 자료가 3일 넘게 갱신되지 않으면 위쪽에 "N일 전 자료"가 주황색으로 뜹니다.
- **4개 언어**: 한국어 · English · 中文 · 日本語. 화면 문구와 AI 번역(요약·제목·혜택·대상)이 모두 바뀝니다.

**처음 열 때와 업데이트될 때 (불러오기 흐름)**
- 앱을 열면 `version.json` → 공지 → 학사일정 → 용어집 순서로 확인하고, 단계별 진행이 있는 불러오기 화면을 띄웁니다.
- 데이터가 하나도 없으면 "아직 공지 데이터가 없어요. 웹 주소로 열거나, PC에서 run_pipeline.bat 을 실행해 데이터를 만들어 주세요" 안내를, 서버에서 받기에 실패하면 이유(인터넷 끊김 등)와 "다시 시도" 버튼을 보여 줍니다. 들어 있는 데이터가 있으면 "들어 있는 데이터로 둘러보기"로 계속 쓸 수 있습니다.
- 데이터가 새로 바뀌면 "새 데이터로 바뀌었어요 — 새 공지 N건 · 마감이 바뀐 공지 N건"으로 알려 줍니다. 처음 불러왔을 때는 "공지 N건을 불러왔어요."가 뜹니다.

**캘린더**: 오늘 탭의 "마감 달력"에 공지 마감(빨강)·행사(초록)·학사일정(파랑)이 월간 달력의 점으로 나오고, 날짜를 누르면 그날 목록이 보입니다. 공지마다 **Google 캘린더** 버튼(캘린더에 추가)이 있어 누르면 일정이 채워진 구글 캘린더 창이 열리고, 설정 탭의 "Google 캘린더와 자동으로 맞추기"에서 **구독 주소**(`data/gongji.ics`)를 복사해 Google 캘린더 → 다른 캘린더 옆 `+` → "URL로 추가"에 붙여 넣으면 새 공지의 마감이 캘린더에 알아서 따라옵니다(구글이 몇 시간 간격으로 확인). 구독 주소는 **웹에 올린 주소**(GitHub Pages 등)에서만 쓸 수 있습니다. 내 컴퓨터(`localhost`)나 파일로 열었을 때는 구글이 읽을 수 없어서 설정 탭이 그렇게 알려 줍니다. 구글 계정에 로그인해서 일정을 직접 써 주는 양방향(OAuth) 연동은 아닙니다.

**보정표 (공지를 사람이 바로잡기)**: AI가 마감일·금액을 잘못 읽었을 때 고치거나, 지난 공지를 숨기거나, 긴급 안내를 띄웁니다. 아래 6번에서 설명합니다.

## 2. 공지 수집 (크롬 확장 v1.1, 자동)

1. 크롬 주소창에 `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기 → **압축해제된 확장 프로그램 로드** → `collector` 폴더 선택 (예전 버전이 있으면 그 카드의 새로고침)
2. 공지줍줍 폴더의 **`setup_auto.bat`** 을 한 번 실행 → 로그인할 때마다 **수신 서버**가 창 없이 켜지고, 매일 07:30에 전체 처리가 한 번 돕니다 (지금 바로 켜려면 `run_server.bat`)
3. 끝. 크롬이 켜져 있으면 확장이 **6시간마다** 홈페이지·국제교육원·AX융합학부 게시판을 백그라운드 탭으로 잠깐 열어 새 글만 받고 닫은 뒤, 수신 서버로 보냅니다. 서버는 1분 뒤 파이프라인을 돌려 웹 앱 데이터까지 갱신합니다.

- 확장 아이콘의 숫자 = 마지막 수집에서 새로 받은 글 수, `!` = 실패한 사이트가 있음. 팝업에서 **지금 수집**, 수집 간격(1~24시간), 사이트 선택, 서버 상태, 새로 받은 공지 제목, 서버의 처리 진행("AI 정리 중 · 공지 합치기·해독 12/40"), **웹 앱 열기**를 봅니다.
- 자동 수집으로 새 공지를 받으면 제목 3개가 든 **알림**이 뜨고, 서버가 AI 정리를 끝내 웹 앱에 반영하면 같은 알림이 "웹 앱에 반영했어요"로 바뀝니다. 누르면 최신 웹 앱이 열립니다(고급 설정에서 끌 수 있음).
- 서버가 꺼져 있으면 다운로드 폴더에 `kku-notices-날짜.json` 으로 저장하고, 다음 `run_pipeline.bat`/예약 실행이 찾아 씁니다.
- 학교 기본 정보(학사일정·요람·규정)와 KIS 강의 시간표는 학기마다 한 번, 팝업의 "학기마다 한 번" 칸에서 받습니다. 받으면 서버로 자동 전달됩니다.
- `http://127.0.0.1:8765/` 를 열면 수신 서버가 웹 앱을 그대로 보여 줍니다(미리보기). `/status` 는 서버 상태.

학교 사이트가 서버·스크립트의 자동 접속을 막기 때문에, 실제 브라우저 안에서 도는 확장으로 모읍니다. 자세한 내용은 `collector/README.md`.

**강의 시간표(선택)**: 학사정보시스템(KIS)에 로그인한 채로 열어 두면 확장이 자동으로 이번 학기 강의 목록을 한 번 받아(자동 받기 방식은 아직 실제 학교 서버로 시험하지 못해, 안 되면 강의계획서조회 → 과목조회에서 조회를 직접 누르면 같은 자료가 저장됩니다), 확장이 화면이 받은 강의 목록(과목명·분반·요일별 시간·강의실)을 저장합니다(교수 이름·수강 인원은 저장 안 함, 서버에 따로 요청하지 않음). 확장 팝업에서 내보낸 뒤 `python pipeline/build_timetable.py`를 돌리면 `data/timetable.js`가 만들어지고, 웹앱의 과목 자동완성에 분반별 요일·시간이 나타나 고르면 시간표에 한 번에 들어갑니다. 요일마다 시간이 달라도 그대로 담깁니다. AI는 쓰지 않고 규칙으로 읽습니다. 학기를 정하지 않으면 과목이 충분한 정규 학기(1·2학기) 중 가장 최근 것을 고르고, 계절학기처럼 과목이 훨씬 적은 다른 학기 자료가 나중에 들어와도 기존 시간표를 덮어쓰지 않습니다(바꾸려면 `--term B01015` 또는 `--force`).

**이음교육시스템 공지(선택)**: 이음(im.kku.ac.kr)에 직접 로그인한 탭에서 확장 아이콘을 눌러 같은 방법으로 수집합니다(로그인 정보·내 이름·학번·작성자는 저장하지 않음). 로그인해야 보이는 글이라 `private` 표시가 붙고, 파이프라인은 기본적으로 공개 데이터에서 제외합니다. 내 컴퓨터에서만 보려면 `python pipeline/build_notices.py --with-private`.

## 3. 로컬 AI로 해독·번역 (파이프라인)

준비 (한 번만):
1. Python 3.10 이상 (추가 설치할 라이브러리 없음)
2. [Ollama](https://ollama.com) 설치 후 모델 받기: `ollama pull qwen3:8b` (약 5GB, RTX 2080 Ti 11GB에서 동작 예상)

> 처음 한 번은 요약을 새로 쓰기 때문에 **공지마다 AI 호출이 대략 한 번 늘어납니다**(저장된 답이 있는 공지는 다시 부르지 않음). 공지가 많으면 처음 실행이 평소보다 오래 걸립니다.

**교차 확인.** AI가 정리한 공지도 규칙(`rules.cross_check`)으로 마감을 한 번 더 읽습니다. '마감·까지'가 적힌 원문 줄의 날짜가 AI 마감과 다르거나 AI가 마감을 못 찾았으면 `check`(규칙이 읽은 날짜와 그 줄)를 붙여 웹 앱이 "원문에서 확인하세요"라고 알려 줍니다. AI 값은 바꾸지 않고, AI가 근거로 든 줄과 같은 줄이면 묻지 않습니다. 붙인 건수는 실행 끝에 "원문 확인 표시 N건"으로 나옵니다.

**AI가 꺼져 있어도 멈추지 않습니다 (규칙 병행).** Ollama가 꺼져 있거나 모델이 없거나 시간 상한(`--max-minutes`, 수신 서버가 부르는 실행은 20분)을 넘기면, 공지마다 ① 저장된 AI 답 ② 직전 결과 ③ 규칙 1차 정리(`pipeline/rules.py`: 마감·혜택을 본문 줄에서 찾고 근거 줄을 남김) 순서로 채워서 게시까지 끝냅니다. 규칙으로 정리한 공지에는 `aiPending` 이 붙어 웹 앱에 "AI 정리 전" 표시가 나오고, 다음 실행에서 AI가 돌면 정밀 해독으로 바뀝니다. 원하는 모델이 없으면 설치된 글 모델 중 같은 계열 → 추천 순서로 대신 고릅니다. 예전에 읽어 둔 포스터 글자는 비전 모델 없이도 다시 씁니다.

먼저 모델이 잘 도는지 시험: `python pipeline/try_model.py` (예시 공지 1건을 처리해 결과와 걸린 시간을 보여 줌, `--model qwen3:4b`로 비교 가능)

실행: **`run_pipeline.bat` 더블클릭** (= `python pipeline/run_all.py`)
0. (자동) 데이터를 zip으로 백업 (`--no-backup`으로 끔, 아래 7번)
1. 공지줍줍 폴더·`collected`·다운로드 폴더의 `kku-reference-*.json`을 저장소에 합치고 학사일정·요람 쪽수·규정 조문 갱신 (`build_reference.py`)
2. `kku-notices-*.json`을 **게시판별 저장소**(`collected/공지/학사공지.json` …)에 합침: 같은 공지는 더 최근 것으로, 새 공지만 추가, 여러 게시판에 같이 올라온 공지는 하나로. 합친 파일은 `collected/원본/`으로 옮김
3. 포스터·첨부 읽기 → 로컬 AI 해독 → **요약 다시 쓰기·검사** → 번역 → `data/notices.js`
4. 저장소 정리: 마감 후 30일(`--keep-days`), 마감을 모르면 올린 뒤 180일 지난 공지를 지우고 `_지운목록.json`에 남김 (다시 내보내도 되살아나지 않음)
5. 게시: `data/notices.json`·`calendar.json`·`glossary.json`·`gongji.ics`(구글 캘린더 구독 파일)·`version.json`을 만들고 설정에 따라 폴더로 복사하거나 git으로 올림 (`--no-publish`로 끔, 아래 5번)

(`settings.json`에 보정표 주소가 있으면 공지를 합치기 전에 그 문서를 받아 `data/overrides.json`을 만듭니다. 받지 못하면 이전에 받아 둔 표를 계속 쓰고 로그에 이유를 적습니다. 아래 6번.)

여러 번 내보내도 파일이 쌓이지 않고 하나의 저장소로 합쳐지며, 이미 처리한 공지는 AI를 다시 부르지 않습니다.

자주 쓰는 옵션: `--vision-model qwen2.5vl:3b`(더 가벼운 비전 모델), `--no-media`(포스터·첨부 읽지 않기), `--offline`(AI 없이 저장된 답에 규칙만 다시 적용), `--model qwen3:4b`(더 가벼운 모델), `--days 30`(최근 30일 글만), `--limit 10`(시험 삼아 10건만), `--with-news`(투데이뉴스 포함), `--timeout 300`(AI 답을 기다리는 최대 초), `--no-cache`(모두 다시 처리)

중간에 멈추거나 끊겨도 같은 명령을 다시 실행하면 처리한 공지는 건너뛰고 이어서 합니다. 한 공지에서 AI가 멈추면 그 공지만 실패로 두고 다음 공지로 넘어갑니다.

처리하지 않는 글: 오래된 글(기본 60일), 합격자·명단처럼 개인정보가 담길 수 있는 글, 학생이 신청할 글이 아닌 게시판(Q&A·교직원 자료실·입찰공지·채용공지), 이미 끝난 일을 알리는 투데이뉴스(보도 기사)

처음 한 번 준비 (포스터·첨부파일 읽기용):

```
pip install -r requirements.txt      (pypdf: pdf, olefile: hwp, pillow: 긴 포스터 나눠 읽기)
ollama pull qwen2.5vl:7b             (포스터 이미지를 읽는 비전 모델, 약 6GB)
```

파이프라인이 하는 일:
0. **포스터 이미지·첨부파일 읽기** (본문이 이미지뿐이거나, 본문이 짧고 첨부가 있는 공지): 학교 사이트에서 이미지와 첨부파일을 내려받아 `pipeline/media/공지id/`에 보관. 첨부는 hwp·hwpx·docx·pdf·xlsx·pptx·zip(안의 파일)에서 글자를 꺼내고, 포스터 이미지와 스캔한 pdf는 비전 모델이 적힌 글자를 옮겨 적음. 비전 모델과 글 모델을 번갈아 올리지 않도록 이 단계를 먼저 몰아서 함
1. 본문이 글자인지 구분 (위 단계로도 읽지 못한 공지만 "본문 확인 불가")
2. 로컬 AI가 마감일·행사 일시·혜택(포인트·금액)·대상·혜택 종류·요약을 정해진 JSON 형식으로 뽑음
3. **안전장치**: 본문 줄마다 번호를 붙여 주고 AI는 근거를 줄 번호로 답함 → 근거 문장은 AI가 쓴 글이 아니라 원문의 그 줄을 그대로 가져옴. 마감·행사 날짜는 근거 줄에 그 월·일이, 금액·포인트는 그 숫자가 있어야 남기고, 요약에 원문에 없는 숫자가 있으면 그 문장을 지움. 일본어·중국어 번역에서 '원'을 '엔(円)'으로 바꾸는 실수도 고침
4. **요약 통일과 품질 검사** (`pipeline/summarize.py`): 작은 로컬 AI는 공지마다 요약의 모양이 들쭉날쭉하기 때문에 요약만 따로 한 번 더 쓰게 합니다. 해요체 두 문장 · 첫 문장은 공지가 무엇인지 · 둘째 문장은 대상 → 마감일 → 혜택 → 일정 순서라는 규칙과 예시를 주고, 결과를 검사합니다. 비었음·너무 짧음·너무 김·목록 기호가 섞임·제목 베끼기·확인된 마감일이나 포인트 숫자가 빠짐 중 하나면 이유를 알려 주고 한 번만 다시 쓰게 합니다. 그래도 안 되면 추출 단계의 초안이 통과하면 그것을, 아니면 **근거가 확인된 정보로 문장을 직접 만들어** 같은 모양을 지킵니다. 어떻게 만들었는지는 공지마다 기록되고, 끝난 뒤 "다시 써서 통과 N건 · 초안으로 대체 N건 · 직접 만든 요약 N건"으로 보여 줍니다.
4-1. 용어집(`data/glossary.js`)의 대응어를 넣어 영어·중국어·일본어로 번역. 번역된 요약에서 한국어 요약의 연도·날짜·금액이 빠졌으면 한 번 다시 번역시키고, 그래도 빠졌으면 그 언어의 요약은 웹 앱이 숨기고 핵심 정보 칸을 보여 줍니다.
5. 학사 규정은 AI가 만들지 않고, 요람 원문 문장을 골라 둔 목록(`pipeline/regulations.json`, 11개)에서 제목 키워드로 연결
6. AI 답을 `pipeline/cache`에 저장 → 다음 실행 때 바뀌지 않은 공지는 AI를 다시 부르지 않음. 검사 규칙만 바뀌어도 저장된 답에 새 규칙만 다시 적용

합격자 발표·명단처럼 개인정보가 담길 수 있는 글은 처리하지 않고, 결과 파일에는 원문 전체가 아니라 짧은 근거 문장만 들어갑니다.

## 5. 웹에 올리고 자동으로 갱신하기 (GitHub Pages)

처음 한 번:
1. GitHub에 새 저장소(예: `gongji-jupjup`)를 만들고 이 폴더를 올립니다. `.gitignore` 때문에 수집 원본 JSON·캐시·백업·`settings.json`은 올라가지 않습니다. **`data/notices.json`, `calendar.json`, `glossary.json`, `gongji.ics`, `overrides.json`, `version.json`은 올라가야 합니다.**
2. 저장소 **Settings → Pages → Branch: main / (root)** → 저장
3. 1~2분 뒤 `https://아이디.github.io/gongji-jupjup/` 으로 접속

그다음부터 파이프라인이 끝날 때 `publish.py`가 `data/notices.json`·`calendar.json`·`glossary.json`·`gongji.ics`·`version.json`(데이터 시각)을 새로 만듭니다. 같은 내용이면 같은 파일이 만들어지므로(일정마다 고정된 번호를 씀) git에 쓸데없는 변경이 생기지 않고, 구글 캘린더에서도 일정이 중복되지 않고 갱신됩니다. 일정 파일이나 용어집을 만들다 실패해도 공지 게시는 계속됩니다. 올리는 방법은 `settings.json`에서 고릅니다.
- `"publish": {"git": true}` → `git add data/ && git commit && git push` 까지 자동 (이 폴더가 git 저장소이고 push 권한이 있을 때)
- `"publish": {"folder": "D:\\서버폴더"}` → 그 폴더로 data 파일만 복사 (이미 다른 방법으로 올리고 있을 때)
- 둘 다 비워 두면 JSON만 만들고, 올리는 건 직접 합니다. 수동으로 돌릴 땐 `python pipeline/publish.py` (`--json`: 파일만 만들기)

**웹 앱의 자동 갱신**: 앱을 열 때와 열어 둔 동안 30분마다 서버의 `version.json`을 읽어, 지금 화면의 데이터보다 새로우면 `notices.json`·`calendar.json`(용어집은 바뀐 경우만)을 받아 화면을 바꿉니다(화면의 "데이터 기준 …" 줄과 "새로고침" 버튼). 받은 데이터 모양이 틀렸거나 샘플 데이터면 쓰지 않습니다. `index.html`을 파일로 열었을 때(`file://`)와 서버가 없을 때는 조용히 꺼집니다.

주소·주기는 `data/config.js`에서 바꿉니다.
- `dataBase`: 비우면 이 웹 앱과 같은 서버의 `data/`. 다른 서버를 쓰려면 CORS를 허용하는 주소여야 하며, 예: `https://raw.githubusercontent.com/내아이디/gongji-jupjup/main/data/`
- `refreshMinutes`: 0이면 자동 확인을 끔
- 구글 드라이브 공유 링크는 브라우저에서 읽는 것을 막아(CORS) 웹 앱의 데이터 원천으로 쓸 수 없습니다. 드라이브는 아래 7번의 **백업 보관**용으로 씁니다.

## 6. 보정표: 수정 가능한 문서로 공지 바로잡기 (구글 문서)

AI가 읽은 값이 틀렸을 때 코드를 고치지 않고 **표에 한 줄 적는 것**으로 바로잡습니다.

| 대상 | 항목 | 값 | 메모 |
| --- | --- | --- | --- |
| 계절학기 | 마감 | 2026-11-28 17:00 | 학과 사무실에서 연장 확인 |
| 자기소개서 클리닉 | 숨김 | 예 | 신청 끝남 |
| (비워 둠) | 알림 | 이번 주 금요일은 휴업입니다 | 긴급 안내 띄우기 |

- **대상**은 공지 id 또는 제목의 일부(긴급 안내는 비워 둠). **항목**은 마감 · 포인트 · 금액 · 혜택 · 메모 · 숨김 · 중요 · 알림 중 하나. `#`으로 시작하는 줄은 설명이라 무시합니다.
- 양식은 `보정표_양식.docx` (표 + 쓰는 법). 구글 드라이브에 올려 **구글 문서로 열면** 그대로 편집 가능한 문서가 됩니다.
- 연결: 문서의 **공유 → "링크가 있는 모든 사용자 - 뷰어"** → 주소를 복사해 `settings.json`(`settings.example.json`을 복사해서 만듦)의 `"remote": {"overrides": "주소"}`에 붙여 넣습니다. 구글 드라이브 데스크톱 앱을 쓰면 동기화된 폴더의 docx 경로(예: `G:\내 드라이브\보정표.docx`)를 적어도 됩니다.
- 파이프라인이 돌 때마다 그 문서를 받아 `data/overrides.json`으로 게시하고, 웹 앱이 이를 읽어 공지에 덮어씁니다. 직접 해 보려면 `python pipeline/remote.py` (`--url 주소`로 시험). 문서를 받지 못하면(비공개·인터넷 끊김·표 없음) 이전에 받아 둔 표를 계속 쓰고, 표가 없으면 보정 없이 진행합니다. 파이프라인은 멈추지 않습니다.
- **왜 파이프라인이 받아 오나**: 브라우저(웹 앱)는 구글 문서를 직접 읽을 수 없습니다(구글의 CORS 규칙). 그래서 이 컴퓨터의 파이프라인이 받아서 같은 서버의 `data/overrides.json`으로 바꿔 올립니다. 구글 시트와 깃허브 CSV 주소는 브라우저가 직접 읽을 수 있어서 `data/config.js`의 `overridesUrl`에 적어도 됩니다.
- **대안(깃허브)**: 구글 문서를 쓰지 않으려면 저장소의 `data/overrides.json`(`{"rows": [["대상","항목","값","메모"], …]}`)을 직접 고쳐서 올려도 같은 효과입니다.

## 7. 백업과 복원

- 파이프라인을 돌릴 때마다 먼저 자동 백업합니다 (`backups/공지줍줍-백업-날짜시각.zip`, 최근 `backupKeep`개(기본 10)만 남김). 수집 저장소(`collected/`), AI 답 저장(`pipeline/cache`), 요람 규정, `data/` 파일이 들어갑니다.
- 수동: `backup.bat` (= `python pipeline/backup.py create`), 목록은 `python pipeline/backup.py list`. `--with-media`(내려받은 포스터·첨부, 용량 큼), `--with-files`(요람 PDF)도 넣을 수 있습니다.
- 복원: `restore_backup.bat` (= `python pipeline/backup.py restore [파일]`, 파일을 안 적으면 가장 최근 것). 복원하기 직전의 상태를 `…-복원전.zip`으로 먼저 저장하므로 되돌릴 수 있습니다.
- **구글 드라이브에 이중 백업**: `settings.example.json`을 `settings.json`으로 복사해 `backupDir`에 드라이브 데스크톱 폴더(예: `G:\내 드라이브\공지줍줍백업`)를 적으면 백업이 그 폴더에도 복사됩니다.
- **내 시간표·설정 백업**: 웹 앱 설정 탭의 "내 설정 백업"에서 시간표·언어·정렬 설정을 파일로 내보내고 불러올 수 있습니다 (다른 기기로 옮길 때도 사용).

혜택 점수 기준(임의): 다드림 포인트 1점 = 1점, 확정 금액 1만 원 = 1점. 상금처럼 받는다는 보장이 없는 혜택과 숫자가 없는 혜택은 추천에서 뺍니다. 기준은 `js/logic.js`의 `WON_PER_POINT`에서 바꿀 수 있습니다.
